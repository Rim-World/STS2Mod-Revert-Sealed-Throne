# 001 总体设计：封印王座升级效果回调（RevertTheSealedThrone）

- 版本：1.0
- 最后更新：2026-11-01
- 依据：`9.SRC/RevertTheSealedThrone/` 现役源码、`1.ADR/001-封印王座升级效果回调方案.md`、`3.DOCS/001-T-封印王座版差异与可行性调研.md`

## 1. 设计目标

把储君（REGENT）先古能力卡「封印王座」（`MegaCrit.Sts2.Core.Models.Cards.TheSealedThrone`）
的**升级效果**从 v0.107.1+ 的「费用 -1」回调为 v0.106 及之前的「添加固有（Innate）」。

- 基础版效果、`OnPlay`、Power、卡图、本地化一律不改。
- 单份产物同时服务 default v0.107.1 与 public beta v0.111.0。
- 游戏更新后若卡片形态改变，mod 自动失效而不是破坏游戏。

非目标：不提供玩家可切换的版本配置（不复用 STS2RevertAnthony 的多版本机制）。

## 2. 运行形态与加载链路

```
游戏启动
  └─ 读取 mods/RevertTheSealedThrone/RevertTheSealedThrone.json
      └─ 加载 dll，触发 [ModInitializer("ModLoaded")]
          └─ ModEntry.ModLoaded()
              ├─ new Harmony(ModId)
              └─ PatchAll(Assembly.GetExecutingAssembly())
```

- 清单：`id=RevertTheSealedThrone`、`version=1.0`、`min_game_version=0.107.1`、
  `has_dll=true`、`has_pck=true`、`dependencies=[]`、`affects_gameplay=true`。
- `pck` 仅含 `mod_image.png`（创意工坊图标，420×420）。
- 无 `ModConfig`，无设置项，功能固定开启。

## 3. 模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| 入口 | `ModEntry.cs` | 挂载 Harmony 补丁；声明 `ModId`；异常只记日志 |
| 行为补丁 | `Patches/SealedThroneUpgradePatch.cs` | `TheSealedThrone.OnUpgrade` Prefix 整体替换 |
| 运行时守卫 | `Patches/SealedThroneShapeGuard.cs` | 校验卡片形态；不符则禁用补丁并记警告 |
| 资源包 | `RevertTheSealedThrone/mod_image.png` | 创意工坊图标 |
| 构建 | `build.ps1`、`export_presets.cfg`、`project.godot`、`*.csproj` | MSIL 构建 → Godot 导入 → 导出 pck → 安装到游戏 |

## 4. 补丁与守卫设计

### 4.1 升级补丁

```csharp
[HarmonyPatch(typeof(TheSealedThrone), "OnUpgrade")]
Prefix(TheSealedThrone __instance) {
    if (SealedThroneShapeGuard.IsSupported() && !__instance.Keywords.Contains(CardKeyword.Innate)) {
        __instance.AddKeyword(CardKeyword.Innate);
        return false;   // 跳过原实现（原实现为 EnergyCost.UpgradeBy(-1)）
    }
    return true;
}
```

- **幂等**：已含 `Innate` 时放行原实现，避免未来官方改回「固有」时重复添加。
- **无需文本补丁**：`CardKeyword` 会自动向卡面描述追加关键词文本与徽记，升级预览与图鉴同步正确。

### 4.2 形状守卫

`SealedThroneShapeGuard.IsSupported()` 校验：能量费 1、星费 3、`CardType.Power`、
`CardRarity.Ancient`、基础版不含 `Innate`。`CanonicalEnergyCost` 为 protected，经反射读取。
结果缓存；不通过时 `Log.Warn` 并永久禁用补丁，直至重启游戏。

`ModelDb` 尚未就绪时（构造器抛异常）返回 `true` 放行，下次访问再评估。

## 5. 数据流

```
升级预览 / 实战升级
  └─ CardModel.MutableClone() + UpgradeInternal()
      └─ TheSealedThrone.OnUpgrade
          ├─ 守卫不通过 → 原实现（费用 -1）
          └─ 守卫通过   → AddKeyword(Innate)，跳过原实现
卡面描述
  └─ 关键词集合含 Innate → 游戏自动追加「固有」文本与徽记
```

## 6. 异常处理

- `ModEntry.ModLoaded` 整体 `try/catch`：`PatchAll` 抛异常（签名变化）时只 `Log.Error`，mod 失效不崩游戏。
- 守卫内部 `try/catch`：反射或 `ModelDb` 异常时放行原逻辑，避免误伤。
- 守卫失败只警告一次（`_warned` 标志）。

## 7. 兼容性设计

| 维度 | 结论 | 依据 |
|---|---|---|
| 107 / 111 | 单 DLL 通用 | 两版 `TheSealedThrone.OnUpgrade` 逐字一致；依赖的 `AddKeyword`、`CardKeyword`、`ModelDb.Card<T>` 签名一致 |
| 本地化 | 无需处理 | 关键词由引擎渲染，文本不走本地化键 |
| 未来版本 | 自动降级 | 形状守卫失配即禁用补丁并告警 |
| 存档 | 无影响 | 不改存档字段，只改升级时的关键词集合 |

## 8. 构建与测试

- 构建：`dotnet build -c Debug`（MSIL，`Private=false` 引用 `sts2.dll` 与 `0Harmony.dll`）
  → Godot `--headless --import` → `--export-pack "Windows Desktop"` → 拷贝 `dll/pdb/json` 到游戏 `mods/`。
- 测试方案（人工）：
  1. beta 111：图鉴升级预览显示「固有」徽记，无「费用 -1」；
  2. default 107：同上；
  3. 战斗内升级后卡牌进入起手抽牌（固有生效）；
  4. 基础版（未升级）行为与原版一致；
  5. 与同系列 mod 同开无冲突。
- 验证状态：构建成功记录在案（0 警告 0 错误）；上述游戏内验证**未记录**。

## 9. 已知风险与后续

1. 未来游戏若把 `OnUpgrade` 逻辑移出派生类，补丁失效；守卫会告警，需重新取证。
2. `AddKeyword` 内部有 `AssertMutable()`；`OnUpgrade` 是游戏标准修改时机，风险低。
3. 无自动化测试与 CI。
