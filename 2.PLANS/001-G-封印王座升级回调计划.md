# 计划：封印王座（The Sealed Throne）升级效果回调为「固有」

状态：**已实施（v1.0 构建完成并安装），待用户实机验证（beta 111 / default 107）**

## 一、背景与目标

将储君（REGENT）先古（Ancient）稀有度能力卡「封印王座」（The Sealed Throne）的**升级效果**从现行版的「费用 -1」回调为 v0.106 之前（含 v0.106）的「添加固有（Innate）」。

- 基础版效果（打出后获得 TheSealedThronePower）与现行版完全一致，不动。
- 适配版本：default v0.107.1 与 public beta v0.111.0。
- 未来版本：以最小补丁面 + 运行时防护实现"无感兼容"（游戏更新后大概率无需改码）。

## 二、已取证结论（2026-08-17）

## 三、技术方案

### 3.1 核心补丁（仅 1 处）

`TheSealedThrone.OnUpgrade` Prefix：

```csharp
[HarmonyPatch(typeof(TheSealedThrone), "OnUpgrade")]
static bool Prefix(TheSealedThrone __instance)
{
    if (SealedThroneShapeGuard.IsSupported() && !__instance.Keywords.Contains(CardKeyword.Innate))
    {
        __instance.AddKeyword(CardKeyword.Innate);
        return false; // 替换原「减一费」实现
    }
    return true;
}
```

### 3.2 形状守卫（轻量，仿 OutbreakShapeGuard）

`ModelDb.Card<TheSealedThrone>()` 校验：`CanonicalEnergyCost == 1`、`CanonicalStarCost == 3`、`Type == Power`、`Rarity == Ancient`、升级前不含 Innate；不符则整体禁用补丁并 Log.Warn。用于未来版本行为变化时自动失效，不崩游戏。

### 3.3 ModEntry（仿 ReaperReplacementMod v3）

`[ModInitializer("ModLoaded")]` + `Harmony.PatchAll` + try/catch（若未来 `OnUpgrade` 签名变化导致 PatchAll 抛异常，mod 静默失效）。

### 3.4 工程与打包

- 模板：ReaperReplacementMod v3（Godot.NET.Sdk/4.5.1、net9.0、MSIL、`NoWarn MSB3270`）。
- 引用：本机游戏 `sts2.dll` + `0Harmony.dll`（`Private=false`）。
- manifest：`min_game_version = "0.107.1"`；本 mod 无任何资源 → 倾向 `has_pck = false, has_dll = true`（纯代码 mod，免 Godot 导出；若加载器强制要求 pck，则补一个空 pck，待实测确认）。

### 3.5 未来版本"无感兼容"策略

1. 依赖面仅 3 个 API（OnUpgrade / AddKeyword / CardKeyword.Innate），111 已确认与 107 一致。
2. 签名变化 → PatchAll 被 try/catch 吞掉，mod 自动失效。
3. 行为变化（如未来官方把升级改回固有）→ 幂等检查 + 形状守卫自动放行原实现，不会重复加固有。
4. 每次游戏更新后按比对清单复查（见七），通常无需改码。

## 八、风险与兜底

1. `has_pck=false` 不被加载器接受 → 补空 pck 或最小 pck（含 manifest 即可）。
2. 未来 `AssertMutable` 语义变化 → PatchAll 级 try/catch 兜底，mod 失效不崩游戏。
3. 若未来版本中升级同时带其他效果（非纯减费）→ 形状守卫只能覆盖已知形状，需按比对清单人工复核。
